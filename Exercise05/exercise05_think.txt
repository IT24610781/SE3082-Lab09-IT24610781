Exercise 05 - THINK Answers
============================================================

1. Why is it a good idea to use a multiple of 32 for the threads
per block?

CUDA schedules threads in groups of 32 called warps.
A block of 512 threads contains 512 / 32 = 16 full warps.
A block size that is not divisible by 32 has a partially filled
final warp, leaving some lanes unused.

Multiples of 32 avoid this particular source of wasted lanes, but
performance also depends on memory access, register use, occupancy,
and other factors. A multiple of 32 alone does not guarantee the
fastest configuration.

2. What happens to the total number of threads launched if you use
500 instead of 512?

For N = 10,000,000:

512 threads per block:
Blocks = (10,000,000 + 512 - 1) / 512 = 19,532
Total threads = 19,532 * 512 = 10,000,384
Extra threads = 384
Active threads in the last block = 128

500 threads per block:
Blocks = (10,000,000 + 500 - 1) / 500 = 20,000
Total threads = 20,000 * 500 = 10,000,000
Extra threads = 0

The 500-thread configuration launches 384 fewer threads, but uses
468 more blocks. Each 500-thread block still needs 16 warps:
15 full warps and one warp with 20 active threads and 12 unused lanes.

Therefore, launching exactly N threads does not automatically make
500 threads per block faster than 512. Performance must be measured.

Keep the if (i < n) bounds check in both versions so the kernel
remains safe when the array size changes.
